## 2. 已锁定的关键决策（Decision Log）

| # | 决策项 | 结论 | 理由摘要 | 出处 |
|---|---|---|---|---|
| D-01 | 技术栈 | **Java 21 + Spring Boot 3 + PostgreSQL + Redis；Vue3 + TS + Vite + Element Plus** | 与团队既有 das-fly / yndky 项目栈一致，上手零成本 | [02](./02-技术选型.md) §1 |
| D-02 | 调度引擎 | **自研轻量调度内核**（独立调度服务），不基于 XXL-JOB/PowerJob 二开 | PRD §12 已有算法级定义；通用框架的任务分片模型与本系统 DAG+队列+资源约束模型阻抗大 | [02](./02-技术选型.md) §3 |
| D-03 | 功能范围 | **原型 18 页全量 + 新增「平台健康度」共 19 页**（回填补数按 V1.0 一并设计），PRD §7 缺口按建议默认值锁定 | 形成完整一期范围，避免二次返工 | [01](./01-总体设计方案.md) §2 |
| D-04 | 交付节奏 | **分批交付，每批停下审阅** | 及时纠偏，避免大返工 | 本文档 §0 |
| D-05 | 线协议风格 | **JSON 统一 snake_case**（`folder_id` 类），Java/TS 侧 camelCase，由全局序列化配置转换 | 避免局部 Converter 类散落 | [07](./07-接口实现规范.md) |
| D-06 | 会话方案 | **Sa-Token**（token-name=Authorization, Bearer 前缀, uuid 风格, 7 天） | 与既有项目一致 | [02](./02-技术选型.md) §4 |
| D-07 | 实时通道 | 日志 **WebSocket**（支持 offset 续传）；列表/看板 **5–10s 轮询** | PRD §13.2 / 缺口 #22 | [06](./06-调度引擎详细设计.md) §7 |
| D-08 | 部署单元 | **server（无状态多副本）+ scheduler（有状态单活选主）** 拆分 | 单体多副本会重复调度；拆分后调度单活、server 可随意扩容 | [01](./01-总体设计方案.md) §4.1 |
| D-09 | 状态真源 | **PostgreSQL 为唯一真源**；Redis 只放可重建的派生态（队列/锁/心跳） | Redis 易失，权威状态必须可审计可回溯；调度器启动从 PG 重建 | [01](./01-总体设计方案.md) §4.2 |
| D-10 | 实时日志通道 | 日志走 **WebSocket**（Redis Pub/Sub 推送，offset 续传），不进主链路 | 日志量是业务数据量的百倍级，轮询会打爆主库 | [01](./01-总体设计方案.md) §4.3 |
| D-11 | 版本不可变 | 工作流版本**发布后冻结**，编辑须「基于此版本新开草稿」 | 任务强绑定版本，可考证「当时执行的是什么」 | [01](./01-总体设计方案.md) §4.4 |
| D-12 | 并发控制单点 | 工作流级/队列级/项目级并发检查**统一收敛到 `ConcurrencyGuard`** | 手动触发与定时触发共用同一入口，避免两处判定不一致 | [01](./01-总体设计方案.md) §4.5 |
| D-13 | 就绪队列数据结构 | **Redis ZSet**（score = 优先级 + 提交时间），支持运行期优先级重估（插队=改 score） | 无需引入 MQ；语义直白、可 O(logN) 重估 | [02](./02-技术选型.md) §1.3 |
| D-14 | 前端画布 | **自研 SVG 画布**（复用原型节点模型），不引入 X6/LogicFlow | 视觉令牌需单一真源；节点内需嵌 Vue 组件；无 CDN 约束 | [04](./04-架构文档-前端.md) §7.3 |
| D-15 | 前端大小写适配 | snake↔camel 转换**只做在网络边界一层**（axios 拦截器），业务代码全 camelCase | TS 类型与运行时一致，避免最隐蔽的字段名 bug | [04](./04-架构文档-前端.md) §4.4 |
| D-16 | 前端权限判定 | 按**权限点**（`schedule:{域}:{动作}`）判定，**不硬编码角色** | PRD §11.2 矩阵变更时前端零改动 | [04](./04-架构文档-前端.md) §5.2 |
| D-17 | 接口幂等 | **`Idempotency-Key` 请求头** + Redis 去重 24h；4 个高危端点后端强制 | 重复点击/网络重试会造成重复业务对象 | [07](./07-接口实现规范.md) §7.2 |
| D-18 | 权限点命名 | **`schedule:{域}:{动作}`**，`@RequiresPermission` 注解式；**47 个权限点**（v3 补 `operator:read`/`workflow:read`） | 与 PRD §11.2 矩阵逐行对齐，可逐格验收 | [07](./07-接口实现规范.md) §5.2 |
| D-19 | 权限与数据范围正交 | 权限点判「**能不能做**」，DataScope 判「**对谁做**」，两者独立组合 | 运维视图/项目隔离/本人限定是三种正交需求，混在一个枚举里必然打架 | [07](./07-接口实现规范.md) §5.3 |
| D-20 | 变量引用语法 | **`${step.{步骤名}.output.{变量名}}`**（采纳 SPEC 版，**回写 B-01**） | 关键字 `step`/`output` 可精确锚定；步骤名可含中文；预留 `${trigger.x}`/`${project.x}` 扩展位 | [07](./07-接口实现规范.md) §9.1 |
| **D-21** | 调度器选主 | **Redisson 分布式锁**（`06 §10.1`），**常备 2 副本**（1 活 1 备），切换 **≤ 45s** | 否掉 PG 租约表方案：一期不值得为 < 10s 多一张表 + 一轮 DB 往返；单副本则切换在物理上不成立 | [06](./06-调度引擎详细设计.md) §10 · [08](./08-非功能与运维方案.md) §2.2 |
| **D-22** | 节点准入余量口径 | **预留账本（reserved）**：Σ 非终态步骤的资源申请量；实际用量只做画像与偏差告警 | 用实际用量做准入必然超卖（峰值滞后：加载期只占 0.5 核 → 连发 10 个 → 30s 后打爆机器） | [06](./06-调度引擎详细设计.md) §5.1 |
| **D-23** | 下发语义 | **at-least-once**；下发带 `(step_instance_id, attempt_no, dispatch_token)` 三元组作执行侧幂等键；非幂等算子回执丢失时**转人工，不自动重跑** | 跨进程 exactly-once 做不到；静默重跑非幂等算子是数据事故 | [06](./06-调度引擎详细设计.md) §4.6 |
| **D-24** | 页面总数 | **20 页**（原型 19 页 + 新增「API 接入」） | PRD §15.5-5 要求平台自身健康可见 + §10.9 API 触发提前纳入一期（v0.2d 评审确认） | [08](./08-非功能与运维方案.md) §5.4 · [07](./07-接口实现规范.md) §6.7 · [DESIGN-api-trigger](../prototype/DESIGN-api-trigger.md) |
| **D-25** | 开放接口 | **API 触发提前纳入一期**：X-API-Key 鉴权 + 作用域白名单 + 限流 + Webhook 通知；新增权限点 2（47→49）、错误码 4、表 4 | 第三方系统接入是采纳率杠杆；PRD §10.9 原列 V1.1，评审确认提前 | [07](./07-接口实现规范.md) §5.2/§4.2 · [05](./05-数据模型设计.md) §3.6 · [DESIGN-api-trigger](../prototype/DESIGN-api-trigger.md) |

## 4. 术语约定（与原型保持一致，勿造同义词）

| 中文 | 实体名 | 说明 |
|---|---|---|
| 项目空间 | `project` | 多租户隔离单元 |
| 集群 | `cluster` | 执行节点集合 |
| 执行节点 | `executorNode` | 实际跑任务的服务器（V0.2 术语，**不叫 node**） |
| 队列 | `queue` | 集群内的调度队列 |
| 凭据 | `credential` | SSH/WinRM/Token 凭证 |
| 算子 | `operator` / `operatorVersion` | 可执行单元及其版本 |
| 工作流 | `workflow` / `workflowVersion` | DAG 编排及其版本 |
| 步骤 | `WorkflowStep` | 工作流内的节点（**不叫 WorkflowNode**） |
| 任务 | `task` / `taskStep` | 工作流的一次运行及步骤实例 |
| 触发器 | `trigger` | 手动/定时/API/事件 |
| 回填批次 | `backfillBatch` | 历史业务日期补跑 |
| 告警规则 | `alertRule` | 事件驱动的通知配置 |
