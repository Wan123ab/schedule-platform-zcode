# 05 · 数据模型设计

> 上游：`PRD §7`（对象清单与实体关系，**基数约束为硬约束**）· `prototype/SPEC-02 §6`（实体字段字典）· `03-架构文档-后端`（六域划分）
> 定位：本文件是**数据库实现的唯一真源**——ER 图、全量 DDL、索引与分区、字典表、迁移策略。
> 约定：DB 层 **snake_case** 单数表名；所有表含 `created_at / created_by / updated_at / updated_by / version / deleted` 六个公共列（§1.4）。

---

## 1. 建模总则

### 1.1 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 表名 | 单数、snake_case、模块前缀可选 | `project` / `workflow_step` / `task_step` |
| 列名 | snake_case | `workflow_version_id` |
| 主键 | `{表名}_id`（业务主键）**或** `id`（自增/雪花） | `task_id` / `id` |
| 外键 | `{被引表}_id` | `credential_ref_id` |
| 索引 | `idx_{表}_{列简写}` | `idx_task_status_created` |
| 唯一约束 | `uk_{表}_{列简写}` | `uk_project_tenant_name` |
| 枚举 | `varchar(32)` + `CHECK`（团队约定，便于排障，见 02 §1.2） | `status varchar(32)` |

### 1.2 主键选型（关键决策）

| 场景 | 主键 | 理由 |
|---|---|---|
| **业务编号可见的实体**（任务/工作流/算子/凭据/项目/集群/回填/告警/审计） | **字符串业务主键**（`TASK-20260921-0001` 等）**+ 内部 `id bigserial`** 作物理主键 | 业务编号要出现在 UI/日志/审计中；但字符串做主键会导致所有外键索引膨胀、B-tree 层级变高。**物理主键用 bigserial，业务编号加唯一索引** |
| 纯关联表（`project_member` 等） | 复合主键 | 天然去重，无需额外列 |
| 高频写入表（`task_log` / `task_step`） | `id bigserial` + 业务列 | 写入性能优先 |

> **落地**：所有表统一用 `id bigserial PRIMARY KEY`，业务编号列（如 `task_id varchar(32)`）加 `UNIQUE`。外键一律引用 `id`（bigint），**不引用业务编号**。

### 1.3 时间与时区

- 存储：`timestamptz`（**带时区**），DB 时区固定 `Asia/Shanghai`；
- 业务日期 `biz_date` 用 `date`（无时区，是"哪一天"而非"哪一瞬"）；
- 所有表统一 `created_at timestamptz NOT NULL DEFAULT now()`。

### 1.4 公共列（全部业务表必备）

```sql
created_at   timestamptz NOT NULL DEFAULT now(),
created_by   varchar(64),
updated_at   timestamptz NOT NULL DEFAULT now(),
updated_by   varchar(64),
version      integer     NOT NULL DEFAULT 0,      -- 乐观锁（调度器 CAS 更新必需）
deleted      boolean     NOT NULL DEFAULT false   -- 逻辑删除（审计/追溯要求，禁止物理删除业务数据）
```

> ⚠️ **`version` 不是可选项**：`03-架构文档-后端` §3.4 规定调度器所有状态更新用 `UPDATE ... WHERE version = :expected` CAS 风格。没有 `version` 列就无法实现。

### 1.5 逻辑删除 vs 物理删除

| 数据 | 策略 | 原因 |
|---|---|---|
| 业务数据（项目/工作流/算子/凭据/告警规则） | **逻辑删除** `deleted=true` | 审计与历史任务回溯需要 |
| 已发布的工作流版本 | **禁止任何删除**（无 DELETE 权限，DB 层 REVOKE） | PRD §7.2 硬约束 |
| 审计日志 | **禁止 UPDATE/DELETE**（DB 层 REVOKE） | 不变式要求（后端 §3.3） |
| 日志内容（`task_log`） | **到期物理删除**（分区 DROP 或 DELETE） | 体积大，无追溯价值（PRD §13.2 归档策略） |
| 运行期任务实例 | 保留（可配置归档） | 排障与画像（PRD §13.4） |

**关键关系与基数**（PRD §7.2，逐条落实）：

| # | 关系 | 基数 | 实现 | 约束落点 |
|---|---|---|---|---|
| R1 | tenant → project | 1:N | `project.tenant_id` | `NOT NULL` + FK |
| R2 | project ↔ user | M:N | `project_member`（携带 `project_role`） | 复合唯一 `(project_id, user_id)` |
| R3 | project ↔ cluster | M:N | `project_cluster` | 复合唯一 |
| R4 | project ↔ queue | M:N | `queue_project_scope` | 复合唯一 |
| R5 | cluster → node | 1:N | `executor_node.cluster_id` | `NOT NULL` + FK（节点不可跨集群） |
| R6 | credential → node | 1:N | `executor_node.credential_ref_id` | **`ON DELETE RESTRICT`** |
| R7 | operator → operator_version | 1:N | `operator_version.operator_id` | FK |
| R8 | operator → project | N:1 | `operator.project_id` | `NOT NULL` + FK |
| R9 | operator_version → param_def | 1:N | `operator_param_def.operator_version_id` | **随版本快照，发布后禁改** |
| R10 | operator_version → output_decl | 1:N | `operator_output_decl.operator_version_id` | 同上 |
| R11 | workflow → workflow_version | 1:N | `workflow_version.workflow_id` | **已发布禁改禁删** |
| R12 | workflow_version → step | 1:N | `workflow_step.workflow_version_id` | FK |
| R13 | step → operator_version | N:1 | `workflow_step.operator_version_id` | **删除前校验引用计数 = 0** |
| R14 | step → step（连线） | M:N | `workflow_edge(source_step_id, target_step_id)` | **发布前环检测** |
| R15 | workflow → trigger | 1:N | `trigger.workflow_id` | FK |
| R16 | trigger → workflow_version | N:1 | `trigger.locked_version_id`（可空=跟随最新） | 默认锁定 |
| R17 | workflow_version → task | 1:N | `task.workflow_version_id` | **任务强绑版本快照** |
| R18 | task → task_step | 1:N | `task_step.task_id` | 实例数 = 版本步骤数 |
| R19 | task_step → task_log | 1:N | `task_log.task_step_id` | 按 `seq` 顺序 |
| R20 | alert_record → task / node | N:1 | `alert_record.target_type + target_id` | 多态引用，无 FK |

## 3. 全量 DDL

> 分区：以 `Flyway` 迁移脚本组织（`V1__baseline.sql` 建基础表，`V2__partition.sql` 建分区表与函数，见 §7）。

### 3.1 域 0：租户、用户、权限

```sql
-- ── 租户 ──────────────────────────────────────────────
CREATE TABLE tenant (
    id          bigserial PRIMARY KEY,
    tenant_id   varchar(32)  NOT NULL,                 -- TENANT-0001
    tenant_name varchar(128) NOT NULL,
    status      varchar(32)  NOT NULL DEFAULT 'ENABLED'
                CHECK (status IN ('ENABLED','DISABLED','ARCHIVED')),
    admin_user_id bigint REFERENCES app_user(id),
    description text,
    created_at timestamptz NOT NULL DEFAULT now(),
    created_by varchar(64),
    updated_at timestamptz NOT NULL DEFAULT now(),
    updated_by varchar(64),
    version    integer NOT NULL DEFAULT 0,
    deleted    boolean NOT NULL DEFAULT false
);
CREATE UNIQUE INDEX uk_tenant_tenant_id ON tenant(tenant_id);
CREATE UNIQUE INDEX uk_tenant_name ON tenant(tenant_name) WHERE deleted = false;

-- ── 用户 ──────────────────────────────────────────────
CREATE TABLE app_user (
    id           bigserial PRIMARY KEY,
    user_id      varchar(32)  NOT NULL,
    username     varchar(64)  NOT NULL,
    display_name varchar(64)  NOT NULL,
    password_hash varchar(128) NOT NULL,               -- BCrypt
    tenant_id    bigint       REFERENCES tenant(id),   -- 可空：平台级用户
    email        varchar(128),
    phone        varchar(32),
    status       varchar(32)  NOT NULL DEFAULT 'ENABLED'
                 CHECK (status IN ('ENABLED','DISABLED','LOCKED')),
    -- 登录锁定（CONTRACT §1：连续 5 次锁定 15 分钟）
    login_fail_count   integer     NOT NULL DEFAULT 0,
    locked_until       timestamptz,
    last_login_at      timestamptz,
    last_login_ip      varchar(64),
    created_at timestamptz NOT NULL DEFAULT now(),
    created_by varchar(64),
    updated_at timestamptz NOT NULL DEFAULT now(),
    updated_by varchar(64),
    version    integer NOT NULL DEFAULT 0,
    deleted    boolean NOT NULL DEFAULT false
);
CREATE UNIQUE INDEX uk_app_user_username ON app_user(username);
CREATE INDEX idx_app_user_tenant ON app_user(tenant_id) WHERE deleted = false;
CREATE INDEX idx_app_user_locked ON app_user(locked_until) WHERE locked_until IS NOT NULL;

-- ── 角色（6 个平台角色，见 03 §3.1）────────────────────
CREATE TABLE role (
    id          bigserial PRIMARY KEY,
    role_code   varchar(64)  NOT NULL,                 -- PLATFORM_ADMIN / OPS / ...
    role_name   varchar(64)  NOT NULL,
    -- ⭐ 2026-10-07 修正（M2 实测 + V6 迁移）：取值口径改为 D-19（07 §5.3）的
    --    ALL / AUTHORIZED_CLUSTER / PROJECT / SELF_CREATED / NONE。
    --    原命名 ('ALL','TENANT','PROJECT','CLUSTER','SELF') 与 ScopeType 枚举无法匹配，
    --    导致 OPS 与 SELF 类角色被解析成 NONE（= 不过滤 ⇒ 越权可见）。
    scope_type  varchar(32)  NOT NULL DEFAULT 'ALL'
                CHECK (scope_type IN ('ALL','AUTHORIZED_CLUSTER','PROJECT','SELF_CREATED','NONE')),
    builtin     boolean      NOT NULL DEFAULT true,
    description text,
    created_at timestamptz NOT NULL DEFAULT now(),
    created_by varchar(64), updated_at timestamptz NOT NULL DEFAULT now(),
    updated_by varchar(64), version integer NOT NULL DEFAULT 0,
    deleted    boolean NOT NULL DEFAULT false
);
CREATE UNIQUE INDEX uk_role_code ON role(role_code) WHERE deleted = false;

-- ── 权限点（Permission）────────────────────────────────
CREATE TABLE permission (
    id         bigserial PRIMARY KEY,
    perm_code  varchar(128) NOT NULL,                  -- schedule:task:stop
    perm_name  varchar(128) NOT NULL,
    module     varchar(64)  NOT NULL,                  -- 所属域
    action     varchar(32)  NOT NULL,                  -- view/create/update/delete/execute
    created_at timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uk_permission_code ON permission(perm_code);

-- ── 角色-权限 ─────────────────────────────────────────
CREATE TABLE role_permission (
    role_id       bigint NOT NULL REFERENCES role(id) ON DELETE CASCADE,
    permission_id bigint NOT NULL REFERENCES permission(id) ON DELETE CASCADE,
    PRIMARY KEY (role_id, permission_id)
);

-- ── 用户-角色（可带数据范围限定）──────────────────────
CREATE TABLE user_role (
    user_id     bigint NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
    role_id     bigint NOT NULL REFERENCES role(id) ON DELETE CASCADE,
    -- 数据范围：为 NULL 表示按角色默认；数组表示限定范围
    scope_ids   bigint[],
    granted_at  timestamptz NOT NULL DEFAULT now(),
    granted_by  varchar(64),
    PRIMARY KEY (user_id, role_id)
);
```

### 3.2 域：项目空间（多租户核心）

```sql
CREATE TABLE project (
    id        bigserial PRIMARY KEY,
    project_id varchar(32)  NOT NULL,                  -- PRJ-0001
    project_name varchar(128) NOT NULL,
    tenant_id bigint NOT NULL REFERENCES tenant(id) ON DELETE RESTRICT,
    description text,
    status    varchar(32) NOT NULL DEFAULT 'ENABLED'
              CHECK (status IN ('ENABLED','DISABLED','ARCHIVED')),
    -- 资源额度（PRD §11.4）
    max_concurrent_tasks integer NOT NULL DEFAULT 5,
    max_waiting_tasks    integer NOT NULL DEFAULT 50,
    -- 项目默认参数（PRD §12.5 继承链第 2 层）
    default_params jsonb NOT NULL DEFAULT '{}'::jsonb,
    -- 项目级默认值（超时/重试/失败策略等，供继承链使用）
    default_timeout_seconds integer,
    default_retry_count     integer,
    default_failure_strategy varchar(32),
    owner_user_id bigint REFERENCES app_user(id),      -- 负责人（不可移除，CONTRACT §2）
    -- 停用统计快照（避免实时 count）
    stat_workflow_count integer NOT NULL DEFAULT 0,
    stat_task_count     integer NOT NULL DEFAULT 0,
    stat_member_count   integer NOT NULL DEFAULT 0,
    created_at timestamptz NOT NULL DEFAULT now(),
    created_by varchar(64), updated_at timestamptz NOT NULL DEFAULT now(),
    updated_by varchar(64), version integer NOT NULL DEFAULT 0,
    deleted boolean NOT NULL DEFAULT false
);
CREATE UNIQUE INDEX uk_project_project_id ON project(project_id);
CREATE UNIQUE INDEX uk_project_tenant_name ON project(tenant_id, project_name) WHERE deleted = false;
CREATE INDEX idx_project_tenant_status ON project(tenant_id, status) WHERE deleted = false;

-- R2：项目成员（M:N，携带项目角色）
CREATE TABLE project_member (
    project_id bigint NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    user_id    bigint NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
    project_role varchar(64) NOT NULL,                 -- PROJECT_ADMIN / OPERATOR_MAINTAINER / BUSINESS / ...
    joined_at  timestamptz NOT NULL DEFAULT now(),
    added_by   varchar(64),
    PRIMARY KEY (project_id, user_id)
);
CREATE INDEX idx_project_member_user ON project_member(user_id);

-- R3：项目可用集群（M:N）
CREATE TABLE project_cluster (
    project_id bigint NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    cluster_id bigint NOT NULL REFERENCES cluster(id) ON DELETE RESTRICT,
    granted_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (project_id, cluster_id)
);

-- R4：队列可用项目范围（M:N，镜像自 queue.projectScope）
CREATE TABLE queue_project_scope (
    queue_id   bigint NOT NULL REFERENCES queue(id) ON DELETE CASCADE,
    project_id bigint NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    PRIMARY KEY (queue_id, project_id)
);
```

### 3.3 域：资产（集群 / 节点 / 队列 / 凭据 / 算子）

```sql
-- ── 集群 ──────────────────────────────────────────────
CREATE TABLE cluster (
    id         bigserial PRIMARY KEY,
    cluster_id varchar(32)  NOT NULL,                  -- CL-0001
    cluster_name varchar(128) NOT NULL,
    cluster_type varchar(64)  NOT NULL DEFAULT 'GENERAL',  -- SPEC §6.2 TODO，默认 GENERAL
    status     varchar(32) NOT NULL DEFAULT 'NORMAL'
               CHECK (status IN ('NORMAL','PARTIAL_ABNORMAL','UNAVAILABLE','MAINTENANCE')),
    -- 资源总量（余量由节点汇总，实时值走 Redis 缓存）
    cpu_total  numeric(10,2) NOT NULL DEFAULT 0,
    gpu_total  numeric(10,2) NOT NULL DEFAULT 0,
    memory_total bigint NOT NULL DEFAULT 0,            -- MB
    disk_total   bigint NOT NULL DEFAULT 0,            -- MB
    -- 统计（定时聚合，非实时）
    node_total  integer NOT NULL DEFAULT 0,
    node_online integer NOT NULL DEFAULT 0,
    node_offline integer NOT NULL DEFAULT 0,
    node_idle   integer NOT NULL DEFAULT 0,
    running_task_count integer NOT NULL DEFAULT 0,
    pending_task_count integer NOT NULL DEFAULT 0,
    history_task_count integer NOT NULL DEFAULT 0,
    last_heartbeat_at timestamptz,
    created_at timestamptz NOT NULL DEFAULT now(),
    created_by varchar(64), updated_at timestamptz NOT NULL DEFAULT now(),
    updated_by varchar(64), version integer NOT NULL DEFAULT 0,
    deleted boolean NOT NULL DEFAULT false
);
CREATE UNIQUE INDEX uk_cluster_cluster_id ON cluster(cluster_id);
CREATE UNIQUE INDEX uk_cluster_name ON cluster(cluster_name) WHERE deleted = false;

-- ── 队列 ──────────────────────────────────────────────
CREATE TABLE queue (
    id         bigserial PRIMARY KEY,
    queue_id   varchar(32)  NOT NULL,
    queue_name varchar(128) NOT NULL,
    cluster_id bigint NOT NULL REFERENCES cluster(id) ON DELETE RESTRICT,
    status     varchar(32) NOT NULL DEFAULT 'ENABLED'
               CHECK (status IN ('ENABLED','DISABLED')),
    max_concurrent_tasks integer NOT NULL DEFAULT 3,
    max_waiting_tasks    integer NOT NULL DEFAULT 50,
    default_priority     integer NOT NULL DEFAULT 0,
    allow_jump_queue     boolean NOT NULL DEFAULT false,
    wait_timeout_seconds integer NOT NULL DEFAULT 3600,   -- 超时→调度失败（PRD §12.2-6）
    waiting_task_count   integer NOT NULL DEFAULT 0,      -- 聚合缓存
    created_at timestamptz NOT NULL DEFAULT now(),
    created_by varchar(64), updated_at timestamptz NOT NULL DEFAULT now(),
    updated_by varchar(64), version integer NOT NULL DEFAULT 0,
    deleted boolean NOT NULL DEFAULT false
);
CREATE UNIQUE INDEX uk_queue_queue_id ON queue(queue_id);
CREATE UNIQUE INDEX uk_queue_cluster_name ON queue(cluster_id, queue_name) WHERE deleted = false;

-- ── 凭据（最敏感，secret 密文存储）─────────────────────
CREATE TABLE credential (
    id         bigserial PRIMARY KEY,
    credential_id varchar(32) NOT NULL,                -- CR-0001
    credential_name varchar(128) NOT NULL,
    credential_type varchar(32) NOT NULL
                 CHECK (credential_type IN ('SSH_KEY','USER_PASSWORD','WINRM','TOKEN')),
    username   varchar(128),
    -- ⭐ 密文，AES-256-GCM；主密钥在环境变量/KMS，永不入库（03 §4.1）
    secret_encrypted text NOT NULL,
    secret_fingerprint varchar(64) NOT NULL,           -- SHA-256，展示后 4 位
    -- 归属：项目级（project_id 非空）或平台级（NULL）
    project_id bigint REFERENCES project(id) ON DELETE RESTRICT,
    ref_count  integer NOT NULL DEFAULT 0,             -- 引用计数（>0 禁删）
    status     varchar(32) NOT NULL DEFAULT 'VALID'
               CHECK (status IN ('VALID','EXPIRING','EXPIRED','REVOKED')),
    last_rotated_at timestamptz,
    expire_at  timestamptz,
    description text,
    creator    varchar(64),
    created_at timestamptz NOT NULL DEFAULT now(),
    created_by varchar(64), updated_at timestamptz NOT NULL DEFAULT now(),
    updated_by varchar(64), version integer NOT NULL DEFAULT 0,
    deleted boolean NOT NULL DEFAULT false,
    CONSTRAINT ck_credential_ref_count CHECK (ref_count >= 0)
);
CREATE UNIQUE INDEX uk_credential_credential_id ON credential(credential_id);
CREATE UNIQUE INDEX uk_credential_name ON credential(credential_name)
    WHERE deleted = false AND project_id IS NULL;
CREATE UNIQUE INDEX uk_credential_project_name ON credential(project_id, credential_name)
    WHERE deleted = false AND project_id IS NOT NULL;
CREATE INDEX idx_credential_status_expire ON credential(status, expire_at)
    WHERE deleted = false;

-- ── 执行节点 ──────────────────────────────────────────
CREATE TABLE executor_node (
    id         bigserial PRIMARY KEY,
    executor_node_id varchar(32) NOT NULL,
    executor_node_name varchar(128) NOT NULL,
    cluster_id bigint NOT NULL REFERENCES cluster(id) ON DELETE RESTRICT,
    ip         varchar(64) NOT NULL,
    os_type    varchar(32) NOT NULL
               CHECK (os_type IN ('LINUX','WINDOWS')),
    connect_type varchar(32) NOT NULL DEFAULT 'SSH'
               CHECK (connect_type IN ('SSH','WINRM','AGENT')),
    -- R6：凭据引用（删除凭据前必须 ref_count=0，此处 RESTRICT 双保险）
    credential_ref_id bigint REFERENCES credential(id) ON DELETE RESTRICT,
    tags       text[] NOT NULL DEFAULT '{}',           -- 标签约束调度（PRD §12.1）
    online_status varchar(32) NOT NULL DEFAULT 'UNKNOWN'
               CHECK (online_status IN ('ONLINE','OFFLINE','UNKNOWN')),
    -- 资源容量与实时用量（实时值同时缓存在 Redis）
    cpu_total    numeric(10,2) NOT NULL DEFAULT 0,
    cpu_used     numeric(10,2) NOT NULL DEFAULT 0,
    gpu_total    numeric(10,2) NOT NULL DEFAULT 0,
    gpu_used     numeric(10,2) NOT NULL DEFAULT 0,
    memory_total bigint NOT NULL DEFAULT 0,
    memory_used  bigint NOT NULL DEFAULT 0,
    disk_total   bigint NOT NULL DEFAULT 0,
    disk_used    bigint NOT NULL DEFAULT 0,
    running_task_count integer NOT NULL DEFAULT 0,
    -- ⭐ v3 新增：节点最大并发步骤数（06 §5.1 预留账本的硬上限）
    --    只按资源（CPU/内存）算余量会低估"进程数/文件句柄/连接数"这类非资源瓶颈，
    --    需要一个显式的步骤数闸门；NULL 表示不限制
    max_concurrent_steps integer,
    enabled    boolean NOT NULL DEFAULT true,
    -- 心跳（15s 上报，45s 判离线；PRD §12.2）
    last_heartbeat_at timestamptz,
    heartbeat_miss_count integer NOT NULL DEFAULT 0,   -- 单次缺失=心跳异常展示，不告警
    -- 最近一次分配任务时间（节点选择第 3 排序键，PRD §12.2）
    last_allocated_at timestamptz,
    created_at timestamptz NOT NULL DEFAULT now(),
```

## 4. 索引设计说明（为什么这样建）

### 4.1 列表页查询路径与索引对应

| 页面 | 查询条件 | 命中索引 |
|---|---|---|
| 任务列表 | `project_id + status + 时间倒序` | `idx_task_project_status_submit` |
| 任务列表（运维视图） | `cluster_id + status` | `idx_task_cluster_status` |
| 任务列表（我的） | `submitter + 时间倒序` | `idx_task_submitter` |
| 工作流列表 | `project_id + status` + `last_run_at` 排序 | `idx_workflow_project_status` + `idx_workflow_last_run` |
| 节点列表 | `cluster_id + online_status` | `idx_node_cluster_online` |
| 节点标签筛选 | `tags @> ARRAY['gpu']` | `idx_node_tags`（GIN） |
| 凭据列表 | `status + expire_at`（即将过期） | `idx_credential_status_expire` |
| 审计列表 | `operated_at` 倒序 + 多维筛选 | `idx_audit_operated` + 各维度索引 |
| 触发器到期扫描 | `enabled + next_fire_time <= now()` | `idx_trigger_next_fire`（部分索引） |

### 4.2 部分索引（Partial Index）的使用原则

**大量使用部分索引**，因为本系统几乎所有查询都带固定条件：

```sql
-- 业务数据默认 deleted = false，索引只建在存活行上
CREATE INDEX ... ON xxx(...) WHERE deleted = false;

-- 调度器只关心活跃状态（含 STOPPING），索引体积可缩小 95%+
CREATE INDEX idx_task_active ON task(status)
    WHERE status IN ('PENDING','SCHEDULING','RUNNING','STOPPING') AND deleted = false;
```

**收益**：调度器每 tick 扫描活跃任务是最高频查询，若索引包含全部历史任务（千万级），单次扫描会随数据量线性变慢。部分索引把索引规模限制在"同时活跃的任务数"（通常 < 1000），扫描恒快。

### 4.3 数组与 JSONB 索引

| 列 | 索引 | 用途 |
|---|---|---|
| `executor_node.tags` | GIN | 标签约束调度（`tags @> ARRAY[...]`） |
| `operator_version.env_vars` | 不建 | 只在读取整行时用，不按内容查询 |
| `task.variable_snapshot` | 不建 GIN | 体积大、无检索需求，仅详情页读取 |
| `audit_log.diff` | 不建 | 同上（如需检索字段名，改为按需加表达式索引） |
| `alert_rule.condition` | 不建 | 规则数量少（< 100），全表载入内存求值 |

> **原则**：**JSONB 只在"读整行"场景使用，不做高频条件查询**。若某字段需要频繁过滤，必须提升为独立列。这是防止 JSONB 滥用导致后期无法优化的关键纪律。

### 4.4 唯一约束中的软删除处理

逻辑删除与唯一约束冲突是常见坑：`WHERE deleted = false` 的部分唯一索引解决之。

```sql
CREATE UNIQUE INDEX uk_workflow_project_name
    ON workflow(project_id, workflow_name) WHERE deleted = false;
-- 效果：同名工作流被删除后，可以重新创建同名工作流
```

| **失败原因（9）** | `EXIT_NONZERO / TIMEOUT / NODE_UNREACHABLE / CREDENTIAL_INVALID / RESOURCE_EXHAUSTED / DEPENDENCY_FAILED / VARIABLE_UNRESOLVED / PLATFORM_ERROR / STOPPED_BY_USER` | `08 §3.5` + 本文件 §3.5 `task_step.fail_reason_code`（**v3 新增列**） |
| **调度决策（4）** | `DISPATCHED / DEFERRED / BLOCKED / SKIPPED` | `06 §14.2.1` + `schedule_decision_log`（**v3 新增表**） |
| **点火状态（3）** | `FIRED / SKIPPED / FAILED` | `06 §11.1.1` + `trigger_fire_log`（**v3 新增表**） |

> ⚠️ **步骤实例状态数量**：CONTRACT §0.4 列了 11 个（含"已跳过"，V1.1），本设计**保留全部 11 个枚举值**，`SKIPPED` 一期不产生但表结构预留——避免 V1.1 上线时要改 CHECK 约束（ALTER CHECK 需全表扫描，千万级 `task_step` 上代价高）。

## 6. 并发与一致性设计

### 6.1 乐观锁（`version` 列）

**所有状态更新走 CAS**（03 §3.4）：

```sql
UPDATE task
   SET status = 'RUNNING', start_time = now(), version = version + 1
 WHERE id = ?
   AND status = 'SCHEDULING'
   AND version = ?;          -- 受影响行数 = 0 → 放弃并重读
```

**为什么不用悲观锁**：调度器是**单线程决策**（03 §6.2），不存在自身并发；需要防的是**调度器 vs 人工操作**（停止/重跑）的竞态。CAS 在这种低冲突场景下几乎无重试成本，且不会像 `SELECT FOR UPDATE` 那样持锁跨网络调用（下发命令可能耗时秒级）。

### 6.2 唯一性保证：业务编号生成

| 编号 | 格式 | 生成方式 | 唯一性保证 |
|---|---|---|---|
| 任务 | `TASK-YYYYMMDD-####` | Redis `INCR task:{yyyymmdd}` | DB `uk_task_task_id` 兜底 |
| 回填批次 | `BF-####` | Redis `INCR bf:seq` | `uk_backfill_batch_id` |
| 工作流 | `WF-####` | Redis `INCR wf:seq` | `uk_workflow_workflow_id` |
| 算子 | `OP-####` | Redis `INCR op:seq` | `uk_operator_operator_id` |
| 项目 | `PRJ-####` | Redis `INCR prj:seq` | `uk_project_project_id` |
| 集群 | `CL-####` | Redis `INCR cl:seq` | `uk_cluster_cluster_id` |
| 凭据 | `CR-####` | Redis `INCR cr:seq` | `uk_credential_credential_id` |
| 告警规则 | `AR-####` | Redis `INCR ar:seq` | `uk_alert_rule_id` |
| 审计 | `AU-####` | Redis `INCR au:seq` | `uk_audit_audit_id` |

**日序列设计说明**（任务编号）：`####` 为**当日**序号（4 位，即每日最多 9999 个任务），跨日归零。Redis key 带日期后缀，天然按日重置。

> **编号回绕处理**：若单日超 9999，序号继续增长为 5 位（`TASK-20260921-10000`），`varchar(32)` 足够容纳。**不做截断或回绕**——回绕会导致唯一约束冲突。

### 6.3 计数列的一致性

`project.stat_*`、`cluster.node_*`、`queue.waiting_task_count`、`credential.ref_count` 都是**冗余计数**。策略：

| 计数 | 更新方式 | 兜底 |
|---|---|---|
| `credential.ref_count` | **事务内即时更新**（新增/删除节点时同步 ±1） | 定时对账任务每日校验（`SELECT COUNT(*)` 比对） |
| `queue.waiting_task_count` | **调度器在出队/入队时更新** | 每分钟由聚合任务校正 |
| `cluster.node_*` | 定时聚合（30s） | 同上 |
| `project.stat_*` | 定时聚合（5min） | 同上 |

**原则**：**冗余计数只用于展示，绝不能作为业务判定的唯一依据**。例如「凭据能否删除」必须**实时 `SELECT COUNT(*)`**，不能只看 `ref_count`（虽然两者应一致，但对账延迟期间必须以实时查询为准）。删除接口实现为：

```sql
-- ① 实时校验（权威）
SELECT COUNT(*) FROM executor_node WHERE credential_ref_id = ? AND deleted = false;
-- ② 校验通过后删除，并检查 ref_count 是否也为 0；不一致则告警（数据异常信号）
```

## 7. 分区、归档与迁移

### 7.1 需要分区的表

| 表 | 预估年增长 | 分区策略 |
|---|---|---|
| `task_log` | **最大**（GB~TB 级） | `RANGE (log_time)` 按日分区 |
| `task_step` | 千万级 | `RANGE (created_at)` 按月分区（V1.1，一期单表） |
| `task` | 百万级 | 一期单表；> 5000 万行再按月分区 |
| `audit_log` | 百万级 | `RANGE (operated_at)` 按月分区 |

### 7.2 `task_log` 按日分区 + 自动清理

```sql
-- 建分区函数（幂等，可重复调用）
CREATE OR REPLACE FUNCTION ensure_task_log_partition(p_date date)
RETURNS void AS $$
DECLARE
    part_name text := 'task_log_' || to_char(p_date, 'YYYYMMDD');
    start_ts  text := to_char(p_date, 'YYYY-MM-DD');
    end_ts    text := to_char(p_date + 1, 'YYYY-MM-DD');
BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_class WHERE relname = part_name) THEN
        EXECUTE format(
            'CREATE TABLE %I PARTITION OF task_log FOR VALUES FROM (%L) TO (%L)',
            part_name, start_ts, end_ts);
        -- 冷存分区不加额外索引（只下载不检索）
        EXECUTE format('CREATE INDEX %I ON %I(task_step_id, seq)',
                       'idx_' || part_name || '_step_seq', part_name);
    END IF;
END;
$$ LANGUAGE plpgsql;

-- 每日定时：预建未来 3 天分区（避免插入时无分区可用）
-- 应用层由 Flyway 迁移 + 定时任务共同保证
```

**清理策略**（PRD §13.2 热存 30 天 / 冷存 90 天）：

| 阶段 | 天数 | 动作 |
|---|---|---|
| HOT | 0 ~ 30 天 | 在线检索；分区保留索引 |
| COLD | 31 ~ 90 天 | 更新 `storage_tier='COLD'`；**DROP 分区索引**（省空间，仅保留下载能力） |
| 到期 | > 90 天 | `DROP TABLE task_log_YYYYMMDD`（**秒级，不产生 vacuum 压力**） |

> **为什么用 DROP 而不是 DELETE**：`DELETE` 千万行会产生大量 dead tuple，需要 `VACUUM FULL` 才能回收空间，期间锁表。`DROP PARTITION` 是元数据操作，**瞬时完成且立即释放磁盘**。这是日志表必须分区的根本原因。

### 7.3 归档

| 数据 | 归档动作 |
|---|---|
| 历史任务（> 180 天） | 导出为归档表 `task_archive` / 或导出 CSV 至对象存储后删除；`PROGRESS` 记录策略 |
| 回填历史 | `backfill_batch` 保留（体积小），关联 `task` 按上述归档 |
| 审计日志 | **永久保留**（合规要求），仅按月分区；不归档不删除 |

### 7.4 权限收口（DB 层保险）

```sql
-- 审计表只增不改不删（03 §3.3 不变式）
REVOKE UPDATE, DELETE ON audit_log FROM flowops_app;
-- 已发布版本禁止删除（应用层已拦，DB 层双保险）
-- 通过触发器或应用层 REVOKE 无法按行粒度控制，故采用：
--   ① 应用层：无对应 API；
--   ② DB 层：审计表完全 REVOKE，版本表通过外键 RESTRICT 保护；
--   ③ 监控层：对 audit_log / workflow_version 的 UPDATE/DELETE 语句做慢日志+告警（异常信号）
```

### 7.5 迁移策略（Flyway）

| 版本 | 内容 |
|---|---|
| `V1__baseline.sql` | 域 0~3 基础表（不含分区表） |
| `V2__partition_task_log.sql` | `task_log` 分区表 + `ensure_task_log_partition` 函数 |
| `V3__governance.sql` | 治理域表（告警、审计）+ `log_view_grant` |
| `V4__seed_roles_permissions.sql` | 种子数据：6 角色 + 权限点全量 + 平台配置默认值 |
| `V5__seed_alert_events.sql` | 种子数据：MVP 5 类告警事件默认规则（**默认开启**，PRD §10.12 设计原则） |

**迁移纪律**：
1. **禁止修改已执行过的迁移脚本**（改历史 = 各环境 schema 不一致）；
2. 大表加列用 `ALTER TABLE ... ADD COLUMN ... DEFAULT NULL`（PG 11+ 秒级完成，不重写表）；
3. 改 `CHECK` 约束在大表上代价高 → **枚举值宁多不少**（§5 已体现）；
4. 生产环境迁移前必须 `EXPLAIN` 验证索引命中。
