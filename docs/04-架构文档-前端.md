**铁律**：

| # | 规则 | 原因 |
|---|---|---|
| F-1 | 只有 `api/modules/*.ts` 可以 import `http.ts` | 请求收敛，便于统一改造（重试/埋点/换 axios） |
| F-2 | 视图**不得**直接拼颜色/字号，只能引用 `styles/tokens.css` 令牌 | DESIGN-01 单一真源 |
| F-3 | 视图不得直接写业务计算（如「进度条百分比」「队列预计耗时」） | 下沉到 composable 或后端 |
| F-4 | 同一段 HTML 结构出现第 2 次，必须抽组件 | 原型阶段已有的约定，工程阶段升级为硬约束 |
| F-5 | 枚举标签/颜色**只能**来自 `useDict()` | 避免「同一状态两种叫法」 |

## 2. 设计系统落地

### 2.1 挂载顺序（`main.ts`）

```ts
import { createApp } from 'vue'
import App from './App.vue'
import { createPinia } from 'pinia'
import ElementPlus from 'element-plus'
import zhCn from 'element-plus/es/locale/lang/zh-cn'
import router from './router'

import './styles/index.css'                // ① 令牌 + 重置 + 氛围层（必须先于 Element Plus）
import 'element-plus/dist/index.css'       // ② Element Plus 基础样式
import './styles/element-override.scss'    // ③ 覆盖（必须最后，方能生效）

const app = createApp(App)
app.use(createPinia())
app.use(router)
app.use(ElementPlus, { locale: zhCn, size: 'small' })   // small 对齐 DESIGN-01 的 33px 控件高
app.mount('#app')
```

> **顺序是关键**：`tokens.css` 定义 CSS 变量，`element-override.scss` 把这些变量灌进 Element Plus 的 `--el-*`。顺序颠倒会出现「深色主题下弹窗白底」这类问题。

### 2.2 样式汇总顺序（`styles/index.css`）

与 DESIGN-01 §9.5 的 `<style>` 组织约定严格对齐：

```
tokens.css  →  theme-light.css  →  reset.css  →  atmosphere.css
            →  skeleton.css  →  element-override.scss
```

### 2.3 令牌搬运规则（原型 → 工程）

**唯一动作：整块复制 + 零修改**。

| 原型（DESIGN-01） | 工程 | 处理 |
|---|---|---|
| `:root{ --bg-void … --r-xl }` | `styles/tokens.css` 的 `:root` | 原样搬运（约 40 个令牌） |
| `body[data-theme="light"]{ … }` | `theme-light.css` | 原样搬运 |
| `body::before / body::after`（光晕 + 网格） | `atmosphere.css` | 原样搬运，`--glow-a`/`--grid-a` 随主题切换 |
| `.panel` / `.btn` / `.st` / 表格样式 | `components/base/*` 的 `scoped` 样式 | **拆分为组件内样式**，但取值仍走令牌 |

**新增令牌的流程**：`DESIGN-01 → tokens.css → 使用`。**禁止**在组件里出现任何十六进制色值——CI 加一条 lint 规则扫描 `#[0-9a-fA-F]{3,8}`（允许出现在 `tokens.css` 与 `theme-light.css` 两个文件内）。

### 2.4 状态语义的单一映射表（`useDict`）

DESIGN-01 §2.5 的「tone + marker」是**前端唯一的状态渲染口径**。落成一张表，业务代码只写状态码：

```ts
// types/enums.ts 节选
// ⚠️ 必须是 9 态全覆盖（05 §3.5 的 CHECK 约束 + 07 §3.5 Java 枚举同为 9 态）
//    Record<TaskStatus, ...> 在 strict 下缺一项即编译失败——这正是要的效果
export const TASK_STATUS_TONE: Record<TaskStatus, Tone> = {
  PENDING: 'idle', SCHEDULING: 'info', RUNNING: 'info',
  STOPPING: 'warn',                        // v3 补：停止中 ≠ 调度中，用 warn 提示"正在收敛"
  SUCCESS: 'ok', FAILED: 'fail', TIMEOUT: 'warn',
  STOPPED: 'idle', PARTIAL: 'warn',
}
export const TASK_STATUS_MARKER: Record<TaskStatus, Marker> = {
  PENDING: 'dot', SCHEDULING: 'pulse', RUNNING: 'spin',
  STOPPING: 'pulse',                       // 仍在动，但与 SCHEDULING 的 info+pulse 不同色
  SUCCESS: 'check', FAILED: 'cross', TIMEOUT: 'clock',
  STOPPED: 'square', PARTIAL: 'dot',
}
```

> **v3 评审修订**：原表只有 8 态，**缺 `STOPPING`**（`05 §3.5` 的 `task.status` CHECK 与 `07 §3.5` 枚举都是 9 态）。后果有二：① `Record<TaskStatus, Tone>` 类型不完整，`vue-tsc` 在 `strict` 下报错（CI 阻塞项）；② 用户点「停止」后、scheduler 收敛为 `STOPPED` 之前（最坏 40s+，见 `06 §10.4`），状态徽标无 tone/marker，渲染为空白。补为 **`warn` + `pulse`**——正在停止应是"警告色 + 收敛动画"，而不是 `SCHEDULING` 的 `info + pulse`。

```vue
<!-- 使用：一处定义，全站一致 -->
<StatusTag :status="task.status" kind="TASK" />
<!-- 内部自动取 tone+marker+中文标签，且满足「颜色+形态」双区分（无障碍要求） -->
```

> **注意（DESIGN-01 §2.5 脚注）**：本项目为运维调度语义，**成功=绿 / 失败=红**。若未来出现行情类页面，必须单独定义色板，不可复用本表。

### 2.5 主题切换与首屏防闪（FOUC）

```html
<!-- index.html 的 <head> 内联，必须早于任何样式表 -->
<script>
  (function () {
    var t = localStorage.getItem('flowops.theme') || 'dark'
    document.documentElement.setAttribute('data-theme', t)
    // 同批读取视图模式（business | ops），避免运维用户首屏闪现业务视图内容
    var vm = localStorage.getItem('flowops.viewMode') || 'business'
    document.documentElement.setAttribute('data-view-mode', vm)
  })()
</script>
```

`useTheme()` 负责运行时切换 + 持久化。**默认深色**（DESIGN-01 的定位是控制台，浅色是可选）。

> **v3 评审补充**：防闪脚本里**同时读取视图模式开关**（PRD §11.3 强制要求运维视图）。只读主题不读视图模式的话，运维用户每次刷新都会看到业务视图内容闪现后再切换——这在运维场景下会被误读为"看到了不该看的数据"。

## 3. 路由、布局与导航

### 3.1 布局骨架（复刻原型，尺寸锁定）

```
┌───────────────────────────────────────────────────────────────┐
│ MainLayout                                                    │
│ ┌──────────┬────────────────────────────────────────────────┐ │
│ │ AppSidebar│ AppTopbar (62px)                              │ │
│ │  230px    │  ← 渐变分割线（DESIGN-01 §5.3 强识别符号）      │ │
│ │           ├────────────────────────────────────────────────┤ │
│ │  导航     │ ViewModeBanner（仅运维视图时占位）              │ │
│ │  激活发光 ├────────────────────────────────────────────────┤ │
│ │           │ <router-view>  padding: 0 22px                 │ │
│ │           │                                                │ │
│ └──────────┴────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────┘
```

> **原型踩坑教训（必须继承到工程）**：
> 1. 顶层包装器在 `body{display:flex}` 下**必须 `width:100%`**，否则宽度塌缩到 `max-content`（原型 `workflow-editor.html` 曾因此把画布压到 140px）。
> 2. 内容区若需滚动，滚动容器**必须显式 `min-height:0` + `overflow-y:auto`**，不能把 `min-height:100vh` 塞进固定高父级（原型 `workflow-detail.html` 曾因此全页不可滚）。
>
> 工程侧改用 `height:100vh` + `flex:1; min-height:0` 的组合，不用 `100vh` 做子元素高度。

### 3.2 全局路由守卫（`router/guard.ts`）

```
beforeEach(to, from, next):
  ├─ 设置 document.title = `${to.meta.title} · FlowOps`
  ├─ 启动顶部进度条
  ├─ 白名单（meta.public：/login /403 /404）→ 放行
  ├─ 无 token → next({ name:'login', query:{ redirect: to.fullPath } })
  ├─ 有 token 但 stores.auth.user 为空 → 调 GET /auth/me 拉取
  │     └─ 失败(40100) → 清 token → 跳 login
  ├─ meta.perm 存在 → usePermission().can(meta.perm)
  │     └─ 不满足 → next({ name:'forbidden' })   // 渲染 403 视图，非静默拦截
  └─ 放行
```

`meta` 约定：

```ts
interface RouteMeta {
  title: string
  public?: boolean          // 免登录
  perm?: string             // 权限点，如 'schedule:task:stop'
  scope?: 'ALL' | 'PROJECT' | 'CLUSTER' | 'SELF'
  keepAlive?: boolean       // 列表页返回时保留筛选与滚动（默认 true）
  breadcrumb?: { label: string; to?: string }[]
}
```

### 3.5 URL 可分享（列表页必须）

## 4. 接口层（重点）

### 4.1 Axios 实例（`api/http.ts`）

```ts
const http = axios.create({
  baseURL: import.meta.env.VITE_API_BASE || '/api/v1',
  timeout: 20_000,
  // ❌ 不要开 withCredentials：本项目认证走 Authorization: Bearer（02 §1.5 / 07 §5.1），
  //    不是 Cookie Session。开它反而要求 CORS 响应不能用 `*`，增加预检复杂度与 CSRF 面。
  headers: { 'Content-Type': 'application/json; charset=utf-8' },
})

// 认证头由请求拦截器注入（见 §4.2），不在实例上写死 —— 便于 SSR/多实例与 token 刷新
```

### 4.2 请求拦截器

```
0. 注入 Authorization: Bearer {token}（来自 auth store；缺失且非 public 路由 → 直接跳登录，不发请求）
1. 生成/透传 trace_id（crypto.randomUUID() **去连字符**，取 32 位小写 hex）→ 写入请求头 X-Trace-Id
2. 写入当前项目上下文 X-Project-Id（仅作"提示"，授权判定一律由服务端按 token 的 scope 决定）
3. 写入视图模式 X-View-Mode: business | ops
4. 幂等写操作附带 Idempotency-Key（防重复提交，见 §4.6）
```

> ⚠️ **安全红线**：`X-Project-Id` 只是服务端日志/排障的辅助信息，**绝不能作为授权依据**（后端 §3.2 已明确「不接受前端传入的项目 ID 作为授权依据」）。
>
> **v3 评审修订**：
> ① 删除 `withCredentials: true`（`04 §4.1`）——它与 Bearer 认证方案冲突，属于从 CONTRACT §0.1 旧版「Cookie Session」沿袭下来的残留；
> ② `X-Trace-Id` 格式**必须与后端 `07 §7.1` I-01 一致**（32 位小写 hex、**无连字符**）。`crypto.randomUUID()` 原始输出含连字符且为 36 位，直接截断会与后端自生成的 `trace_id` 格式不一致，导致同一请求在前后端日志里出现两个不同 `trace_id`，排障链路断裂。前端生成不合规则时，后端应**忽略并自行生成**（`07 §7.1`）。

### 4.3 响应拦截器

```
成功：
  res.data.code === 0 → 直接 resolve res.data.data（业务层拿到的就是 data，不再层层 .data.data）
  分页响应自动识别 { total, page, page_size, records[] } → 保持原结构
                                    ↑ 线协议是 snake_case（D-05）；经 §4.4 拦截器后业务层拿到的是 camelCase

失败（按 CONTRACT §12 错误码分流）：
  ├─ 40100 未登录        → 清 auth store → 跳 login（携带 redirect）→ 静默，不弹 Toast
  ├─ 40101 账号已锁定     → 跳 login 并携带 lockedUntil，登录页渲染 mm:ss 倒计时
  ├─ 40300 无权限        → Toast「无权限执行该操作」；由调用方决定是否降级为 403 视图
  ├─ 40400 资源不存在     → 调用方处理（详情页渲染 NotFound 态）
  ├─ 40900 状态冲突       → Toast 展示服务端 message（如「该版本已发布，不可编辑」）
  ├─ 42201/42202/42210/42231/42232（业务约束）→ 交由调用方按 code 分支处理，默认 Toast
  ├─ 40001 参数校验失败   → 若带 errors[]，交由表单映射到字段级错误提示
  ├─ 50000 内部错误      → Toast「服务异常，请稍后重试（trace：xxx）」
  └─ 50300 依赖不可用     → Toast「调度服务暂不可用」+ 顶部持久横幅
网络层错误（超时/断网）→ 统一的网络错误 Toast；GET 自动重试 1 次（退避 800ms），写操作不自动重试
```

**关键约定**：拦截器**只负责「无歧义」的错误**（登录失效、网络错误）。凡是需要**业务分支**的错误码，一律透传给调用方，不在拦截器里 `Toast 掉`——否则页面级降级态（如回填页的 `noperm` 视图）永远做不出来。

### 4.4 snake_case ↔ camelCase 适配（D-15 落地）

**背景**：`01-总体设计方案` D-05 定下「线协议 global snake_case，Java/TS 层 camelCase」，本条 D-15 是其在**前端侧的落地方式**。

> **v3 评审修订（消除三处矛盾）**：关于"键名到底转不转"，曾存在三个版本——`02 §3.3`（前端不做转换、TS 类型按 snake 写）、本文 §1.2 目录注释（snake）、本文 §4.4（拦截器转换、业务代码全 camelCase）。**以本文 §4.4 为准**（即 `00 §2` 记录的 D-15），`02 §3.3` 与 §1.2 注释已同步修正。
>
> 理由：TS 类型必须与运行时一致，否则 `Record`/解构一类的静态检查全部失效；`07 §3.1` 的效果矩阵里「TypeScript: camelCase + 边界转换仅在 axios 拦截器」也与之呼应。
>
> 另注：CONTRACT-API §头注写「接口文档一律按 camelCase 书写」，那是**契约文档草案**的书写口径（便于与 §6 实体字典对齐）；线协议仍是 snake_case，且 CONTRACT 的 `traceId` / `pageSize` 等已在 `07 §12` 回写清单中改为 snake_case。文档书写口径 ≠ 线协议口径，二者不可混淆。

**前端必须做适配，不能假设 axios 自动转换**（否则 TS 类型与运行时不一致，是最隐蔽的 bug 来源）。

```ts
// utils/casename.ts
export const toCamel = (s: string) => s.replace(/_([a-z0-9])/g, (_, c) => c.toUpperCase())
export const toSnake = (s: string) => s.replace(/[A-Z]/g, (c) => '_' + c.toLowerCase())

// 深转换（数组/对象递归；Date/File/Blob 原样返回）
export function deepCamel<T>(input: unknown): T
export function deepSnake(input: unknown): unknown
```

**放置位置**：在**请求拦截器出口**做 `deepSnake(req.data)`，在**响应拦截器入口**做 `deepCamel(res.data)`。

**分层原则**：

| 层 | 命名 | 说明 |
|---|---|---|
| `api/types/*` | **camelCase** | 与 CONTRACT-API 文档完全一致，便于对照评审 |
| `api/modules/*` | camelCase | 请求参数/返回值同此 |
| `types/domain.ts` | camelCase | 前端领域模型 |
| 视图 / store / composable | camelCase | 无感知 |

**收益**：全站业务代码只认 camelCase；snake 只存在于网络边界的一层适配器里。若未来需要改协议风格，只改这一处。

> **⚠️ 待确认（F-01）**：`trace_id` 已在 `03-架构文档-后端` 定为 snake（因全局 Jackson 配置）。因此前端 `ApiResult` 类型应定义为 `{ code, message, data, trace_id }`，但 CONTRACT-API §0.2 写的是 `traceId`。**需回写契约文档**（见 §9）。

### 4.5 `useRequest`（请求时序收敛）

```ts
const { data, loading, error, refresh, cancel } = useRequest(
  () => taskApi.list(query.value),
  { immediate: true, watch: [query], keepPrevious: true }   // keepPrevious：翻页时不闪白
)
```

- `watch` 触发时**自动取消上一个未完成请求**（`AbortController`）——避免慢请求覆盖快请求的经典竞态（筛选快速切换时必现）；
- `keepPrevious: true` 时保留上一页数据直到新数据到达，避免表格闪空。

### 4.6 幂等与防重复提交

以下操作前端必须**按钮 loading + 禁用 + 幂等键**三重保护：登录、任务提交、回填提交、算子发布、工作流发布、凭据轮换、告警渠道测试。

```ts
// Idempotency-Key 由前端生成并在「同一次用户意图」内保持不变
const key = useIdempotencyKey(['backfill-submit', workflowId, bizFrom, bizTo])
```

> **v3 评审修订**：请求头名是 **`Idempotency-Key`**（`07 §7.2` / `07 §3.4`），不是 `X-Idempotency-Key`；且按 `07 §7.2` 的口径是**前端必带、后端不强拒**（后端一期只对 4 个高危端点强制校验）。

**回填特有闸门**（CONTRACT §8）：提交必须携带 `confirmedPreviewHash`，该值来自预览响应。**前端需在预览后配置发生任何变更时立即作废该 hash**（否则用户会收到 `42231`）。

### 4.7 轮询策略

| 场景 | 周期 | 备注 |
|---|---|---|
| 工作台聚合（`/dashboard/*`） | **5s** | 仅当页面可见（`document.visibilityState`），隐藏即暂停 |
| 任务列表（有 RUNNING/SCHEDULING 项时） | 5s | 全为终态时降为 30s |
| 任务详情（DAG 执行中） | 3s | 步骤状态推进 |
| 集群详情 / 节点详情 | 10s | 资源水位 |
| 平台健康度（第 19 页） | **10s** | `07 §6.7`；聚合视图，不走 WebSocket |
| 步骤日志 | **WebSocket 优先，握手失败自动降级 1s 轮询** | 降级后用 HTTP `offset` 补齐；WebSocket 日志链路**必须保留** HTTP 降级通道（企业代理常阻断 WS） |
| 其他列表页 | 不轮询 | 手动刷新 |

> **v3 评审修订**：原表写「步骤日志 = WebSocket（**不回退轮询**）」，与 `07 §7.5`（握手失败 → 降级轮询 1s）、`09` M1 DoD（M1 就实现 HTTP 降级通道）、`09` T-05 风险项三处冲突。企业代理剥离 WebSocket 是常见现象，「不回退」等于把日志页做成"某些用户永远看不到日志"。已改为**优先 WS + 自动降级**。

`usePolling` 必须实现：页面隐藏暂停、连续失败 3 次退避到 30s、卸载时清理定时器。

## 5. 状态管理（Pinia）

### 5.1 store 划分原则

| store | 生命周期 | 内容 |
|---|---|---|
| `auth` | 登录 → 登出 | user、roles[]、permissions[]、dataScope、token 存在标记 |
| `app` | 应用级 | theme、sidebarCollapsed、viewMode（business/ops）、globalLoading |
| `dict` | 应用级（启动拉一次） | 全部枚举字典 `{value,label,tone,marker}` |
| `project` | 切换项目时 | currentProjectId、可见项目列表、可见集群列表 |
| `notify` | 应用级 | Toast 队列、未读告警数 |

**不放进 Pinia 的东西**（重要）：
- ❌ 列表数据、详情数据 → 用 `useRequest` 局部管理（放进 store 会导致跨页面脏数据与内存泄漏）；
- ❌ 表单临时态 → 组件内 `ref`；
- ❌ 任何服务端权威状态的「本地副本」→ 前端不做业务真源。

```ts
  /** 数据范围是否覆盖目标 */
  const canOn = (perm: string, target: { projectId?: string; clusterId?: string; ownerId?: string }) => { ... }
  return { can, canOn }
}
```

**四态全覆盖**（DESIGN-01 §10 自检项）：`loading` 骨架屏 / `empty` 空态（含「清空筛选」引导）/ `error` 错误态（含重试）/ `normal`。

### 6.3 表单与校验

## 7. 工作流画布（前端最复杂部分）

### 7.1 能力清单（对齐 PRD §10.8 画布能力）

| 能力 | 实现 |
|---|---|
| 节点拖拽新增（算子库 → 画布） | HTML5 DnD，落在网格吸附（`gridSize: 20px`） |
| 节点拖动 / 框选 / 多选 | SVG 层统一处理 pointer 事件 |
| 连线（输出端口 → 输入端口） | 贝塞尔曲线；禁止自环与重复边 |
| 画布缩放（滚轮）/ 平移（空格拖拽或中键） | `viewBox` 变换，缩放范围 0.4× ~ 2.0× |
| 小地图 | 右下角缩略图（节点数 > 20 时显示） |
| 自动布局 | 「整理画布」按钮，按拓扑层级从左到右分层（Sugiyama 简化版：分层 + 层内按入度排序） |
| 备注节点 | `stepType=NOTE`，不参与执行与校验（规则 1 明确"备注除外"） |
| 撤销 / 重做 | 命令栈，最多 50 步 |
| 离开前拦截 | `onBeforeRouteLeave` + `beforeunload`，有未保存变更时弹确认 |

### 7.2 DAG 数据模型（前端内存态）

```ts
interface DagModel {
  steps: DagStep[]           // id, name, stepType, operatorId, operatorVersionId,
                             // params{}, resourceRequest{}, nodeTags[], mutexGroup,
                             // failureStrategy, timeoutSeconds, x, y
  edges: DagEdge[]           // id, source, target
}
```

**保存契约**（CONTRACT §6.2）：**DAG 整包保存，不做步骤级增量接口**。因此前端维护一份完整 `DagModel`，保存时 `PUT /workflow-versions/{versionId}` 整体提交。好处：无中间态不一致；代价：需要前端自己做变更检测（`hasDraftChanges`）。

### 7.3 为什么自研画布而不是 X6 / LogicFlow（D-14）

| 理由 | 说明 |
|---|---|
| 视觉一致性 | DESIGN-01 的发光/渐变/dim 底是自定义 CSS，图库内置节点样式改造成本高于重写 |
| 依赖体积 | 原型已验证「纯 SVG + pointer 事件」足够支撑本项目规模（单工作流 ≤ 100 节点） |
| 可控性 | 节点内需要嵌 `StatusTag`、`MiniTrend` 等 Vue 组件，图库的自定义节点 API 反而绕 |
| 无 CDN 约束 | 内网部署，图库的字体/资源加载易踩坑 |

> **风险与止损**：若一期发现自研画布工作量超出预期（> 10 人日），**降级方案**为引入 LogicFlow 并接受视觉妥协——但节点渲染仍走自研 Vue 组件。此决策点在 **M3 开工前复核**（F-04）——M3 才是编排域里程碑，与调度引擎无关。

## 8. 原型缺陷 → 工程预防清单（⭐ 从踩坑中提炼）

> 以下每一条都是原型阶段**真实发生过**的问题，工程侧必须在代码规范/CI 层面预防。

| # | 原型现象 | 根因 | 工程预防 |
|---|---|---|---|
| F-7 | `workflow-detail` 无法下滑 | `min-height:100vh` 裸包装器塞进固定高父级 → 全页无滚动容器 | 布局用 `height:100vh + flex:1 + min-height:0`；内容区统一 `overflow-y:auto`；**禁止** `min-height:100vh` |
| F-8 | `workflow-editor` 画布被压到 140px | `body{display:flex}` 把顶层包装器当 flex item，缺 `width:100%` → 宽度塌缩 | 顶层布局容器强制 `width:100%`；用 Playwright 断言「画布宽度 ≥ 视口 60%」 |
| F-9 | 分页按钮竖排 | 容器与按钮**同名类**（`.pg` 双用途），按钮样式污染容器 | 类名职责单一；用 BEM 或 `F` 前缀（`FPagePager`）；E2E 断言「分页项 `flex-direction` 为 row」 |
| F-10 | 分页当前页不高亮 | JS 输出 `' on'`，CSS 定义 `.active` | 类名常量集中定义（`CLASS.ACTIVE`），禁止字面量散落 |
| F-11 | 定时触发器点击"没反应" | 两个入口指向同一 URL，无 query 区分 → 视图无变化 | 同页多入口**必须**用 query 产生可感知差异；E2E 断言点击后 URL 变化 + 视图差异 |
| F-12 | 侧栏死链 | 导航 href 写错且无校验 | 侧栏由路由表**生成**（禁止手写 href）；E2E 遍历全部导航项断言 `router.resolve` 不报错 |

**CI 阻塞项**（`vue-tsc` + ESLint + 上述 E2E 断言）：
1. 无 `any`（除 `api/types` 的边界声明）；
2. 无硬编码色值（`tokens.css`/`theme-light.css` 例外）；
3. 无手写导航 href；
4. 全部列表页 URL 可分享（query 同步存在）。
