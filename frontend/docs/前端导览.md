## 1. 一张图看懂前端在做什么

```
浏览器里的一切前端代码，本质上只做三件事：

  ① 把数据 变成 画面      → Vue 组件（views/ + components/）
  ② 把画面 变成 请求      → api/（axios 封装，唯一出口）
  ③ 在页面之间 跳转/守卫   → router/（路由表 + 权限守卫）

  跨页面共享的少量状态（登录态/主题/视图模式） → stores/（Pinia）
  全站视觉的唯一来源                          → styles/tokens.css（原型搬运，零修改）
```

对应到目录（`frontend/src/`）：

| 目录 | 职责 | 铁律 |
|---|---|---|
| `api/` | 请求层：`http.ts` 封装 axios，`modules/` 按域分文件 | 只有 modules 可以用 http（F-1） |
| `components/` | 跨页面复用的组件（`biz/` 业务件） | 出现第二次的结构必须抽到这里（F-4） |
| `composables/` | 无界面的逻辑复用（权限判定、轮询…） | Vue 版的"公共函数库" |
| `layouts/` | 布局壳：侧栏 + 顶栏 + 内容区 | 从原型 base.css 继承样式 |
| `router/` | 19 页路由表 + 全局守卫 | 权限点一律取 `constants/permissions.ts` |
| `stores/` | Pinia 跨页状态 | **列表/详情数据不进 store**（会脏、会漏） |
| `styles/` | tokens.css 唯一视觉源 | 组件内禁止十六进制色值（F-2） |
| `views/` | 19 个页面，一页一文件 | 页面只做"组装"，业务逻辑下沉 |

## 2. 五个必须先理解的 Vue 机制（5 分钟版）

**① 单文件组件（.vue）= 三段式**
```vue
<script setup lang="ts">  ← 逻辑（数据、函数）
<template>               ← 画面（HTML 模板，双大括号插值）
<style scoped>           ← 样式（scoped = 只作用于本组件）
```
`<script setup>` 是 Vue 3 推荐写法：顶层声明的变量和函数**自动**对模板可见，不用手工注册。

**② 响应式：ref / reactive / computed**
- `ref(0)` 把普通值变成"响应式"值 —— 它一变，所有用到它的画面自动更新。在 script 里要写 `.value`，模板里不用。
- `reactive({a:1})` 同理，用于对象。
- `computed(() => a.value * 2)` 是**推导值**：依赖没变就不重算（有缓存），等价于"屏幕上显示的公式"而不是"存下来的结果"。

**③ 组件通信：props 向下、emit 向上**
```vue
父：<StatusTag :status="row.status" />        ← :status 是传参（props）
子：defineProps<{ status: TaskStatus }>()     ← 子组件声明入参类型
子：<button @click="$emit('refresh')">        ← 子组件向上报事件
父：<StatusTag @refresh="reload()" />         ← 父组件监听处理
```
口诀：**数据向下流，事件向上冒**。绝不反向，绝不跨级。

**④ 条件与列表渲染**
- `v-if="cond"`：条件渲染（整个节点存在/不存在）；`v-show` 是显示/隐藏。频繁切换用 v-show。
- `v-for="item in list" :key="item.id"`：列表渲染。**key 必须给且稳定**（Vue 靠 key 复用节点）。

**⑤ 生命周期与守卫**
- `onMounted(() => {...})`：组件挂载后执行（首屏拉数据在这里）。
- `router.beforeEach`：每次页面跳转**前**运行 —— 本项目登录检查和权限检查都在这一个函数里（router/guard.ts）。

## 3. 一次请求的完整旅程（跟一遍就懂了）

以登录为例，从点击按钮到画面更新：

```
LoginView.vue 的 submit()
  → authApi.login()                api/modules/auth.ts（唯一允许发请求的层）
  → http 实例（axios）              api/http.ts
      请求拦截器：注入 Authorization: Bearer token
                 注入 X-Trace-Id（32 位 hex，与后端日志同一标识）
                 注入 Idempotency-Key（写操作防重复提交）
                 data 做 deepSnake（camelCase → snake_case，D-15）
  → 后端返回 { code, message, data, trace_id }
      响应拦截器：res.data 做 deepCamel（snake → camel）
                 code === 0   → 直接把 data 返回给调用方（业务层拿到的就是业务数据）
                 code === 40100 → 清会话、跳登录（拦截器统一处理，页面无感）
                 其余无歧义错误 → 统一 Toast；需要页面自己分支的码（40300/40001…）透传
  → auth.setSession(...)           stores/auth.ts（token + 权限点列表进 Pinia + localStorage）
  → router.push('/dashboard')      跳转触发 beforeEach 守卫 → 权限通过 → 渲染
```

**为什么键名要转换？** 数据库与线协议用 snake_case（`workflow_id`），TS/业务代码用 camelCase（`workflowId`）。转换**只发生在 axios 拦截器这一处**（D-15），业务代码全 camelCase，TS 类型才与运行时一致。

## 4. 状态管理怎么用（Pinia 三句话）

1. store 只放**跨页面共享**的轻量态：登录态（auth）、主题/视图模式（app）、当前项目（project）。
2. 列表数据、详情数据**永远不进 store** —— 用 `useRequest` 在页面内部管理，"请求即刷新"，否则必然出现跨页脏数据。
3. 修改 store 一律走 actions（`auth.setSession(...)`），不在组件里直接改内部字段。

## 6. 原型踩坑 → 工程硬约束（docs/04 §8 精选）

| 曾经的坑 | 现在的规矩 |
|---|---|
| 页面无法滚动（min-height 塞进固定高父级） | 布局只用 `height:100vh + flex:1 + min-height:0`（见 MainLayout） |
| 画布被压成 140px（顶层容器缺 width:100%） | 顶层布局容器强制 `width:100%` |
| 分页按钮竖排（容器与按钮同名类） | 类名职责单一，业务组件加 `biz/` 前缀隔离 |
| 侧栏死链（手写 href 写错） | 侧栏由路由表**生成**（AppSidebar 遍历 navGroups） |
| 同一状态两种叫法/颜色 | 标签与颜色只能来自 enums.ts 映射表（StatusTag 查表） |

## 7. 提问自查清单（改前端代码前）

1. 这个值变了画面会自动更新吗？→ 必须是 ref/reactive/computed，普通变量不会
2. 这个数据跨页面用吗？→ 否则不进 store，放页面内
3. 颜色/字号是令牌吗？→ 否则回 tokens.css 补令牌
4. 这段结构是第二次出现吗？→ 是就抽组件
5. 新的 Vue 机制用到了吗？→ 在使用处加两句机制注释（D-26 第 4 条）
